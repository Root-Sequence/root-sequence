# Recovery Paths

Recovery is not a single action. It is a set of possible paths.

Different systems rely on different combinations of these paths.

## Restoration

Recovering from backup to a previous state.

Example:
- restoring a database from snapshot

## Rollback

Reverting to a known good configuration or version.

Example:
- undoing a deployment

## Redundancy

Switching to a backup component.

Example:
- failover to secondary server

## Rerouting

Redirecting flow through alternate paths.

Example:
- traffic routed through different node

## Graceful degradation

Continuing with reduced functionality.

Example:
- service runs without non-critical features

## Rebuild

Reconstructing the system from scratch.

Example:
- reinstalling host and redeploying services

## Repair

Fixing broken components directly.

Example:
- correcting misconfiguration
- repairing trust in a social system

## Knowledge recovery

Reconstructing lost understanding.

Example:
- rediscovering undocumented setup steps

## What makes recovery real

Recovery depends on:

- tested backups
- accessible tools
- documented procedures
- distributed knowledge
- available time
- clear system boundaries
